Codex Local Architecture — Security Architect Review
AuthN/Z

Identity federation via SAML 2.0 (FMSSO Ping → auth.openai.com); MFA enforced at IdP
OAuth 2.0 Authorization Code grant + PKCE (S256) for token issuance; OIDC id_token carries identity claims
Authorization enforced at ChatGPT Enterprise via RBAC claims in signed JWT (Codex Local/Cloud toggles per group)
Disable API-key login at admin level — single largest SSO-bypass vector
SAML SLO does not revoke issued OAuth tokens; revocation must happen at OpenAI admin console

Ports / Protocols

TLS 1.2+ outbound: auth.openai.com:443, chatgpt.com:443, <ping-host>:443
Inbound: loopback bind on 127.0.0.1:1455 (OAuth callback) — never exposed beyond localhost
Block api.openai.com:443 at egress unless API-key path is explicitly sanctioned
No raw SAML or OIDC discovery endpoints exposed corp-side

Credential Management

Three secrets per user: id_token (JWT), access_token (JWT), refresh_token (opaque)
Mandate OS keyring storage (cli_auth_credentials_store = "keyring"); deprecate ~/.codex/auth.json
Short-lived access_tokens with silent refresh; rotate refresh_tokens on use
Treat auth.json as credential equivalent — EDR DLP rule to detect copy/upload
Service-account / shared dev-box scenarios: explicitly forbidden (tokens are user-bound)

Infrastructure Security

Dev machines: full-disk encryption + EDR + MDM-enforced OS patch baseline required
Codex CLI/IDE/app versions pinned via MDM; binary integrity verified at install
Ping/IdP runs inside ESS2.0 perimeter; auth.openai.com + ChatGPT backend are external (out-of-perimeter)
Codex Cloud sandbox is OpenAI-resident; treat as third-party hosted compute for data-residency review
No private-link / VPC peering option today — all traffic over public TLS

Data Security

Default to Codex Local: source code never leaves Corporate DataCenter (only prompt context crosses to OpenAI)
Codex Cloud: repo cloned into OpenAI-hosted container — requires explicit data-classification approval per repo
Cloud internet-access toggle: off by default; allowlist only for approved tasks
ZDR + data-residency settings inherited from ChatGPT Enterprise contract — verify match against your obligations
Prompt content + agent outputs subject to ChatGPT Enterprise retention policy (not Codex-specific)

Application Security

PKCE prevents auth-code interception on the loopback callback (no client secret in public client)
state parameter enforces CSRF protection on the callback
App Server (local) sandboxes tool execution; destructive shell commands gated by user-approval prompts
Prompt-injection risk in repo content — especially Cloud mode, where remote files become agent input
Pin model and harness versions in enterprise policy to avoid uncontrolled behavior changes

Operational Security

SCIM-driven provisioning + automatic deprovisioning from FMSSO Ping
Documented revocation runbook: ChatGPT admin token revoke → IdP disable → keyring purge (SLO alone is insufficient)
Codex seat assignment governed by access-review process (quarterly)
Change management for admin toggles (Codex Local/Cloud, internet-access, retention) — treat as production config
Incident playbook for compromised dev machine: remote wipe + token revocation + audit-log review

Logging / Monitoring / Threat Model

Forward ChatGPT Enterprise Compliance API logs + FMSSO Ping SSO logs to SIEM; correlate on user identity
Alert on: new-device tokens, off-hours logins, Cloud task spikes, repeated SAML/OAuth failures, internet-egress from Cloud sandbox
Threats explicitly modeled: (1) stolen auth.json → token replay; (2) API-key bypass of SSO; (3) prompt injection from repo content; (4) malicious MCP/tool integration exfiltrating data; (5) shadow IT (personal ChatGPT account used on corp machine)
No native session-binding to device — token portability is a known gap; mitigate with EDR + DLP

GenAI Security (Codex-specific)

Prompt injection from source code, comments, READMEs, and dependencies — treat all repo content as untrusted input to the agent
Tool-use abuse: shell, file write, network egress — enforce explicit approval mode, not auto-approve
Output validation: agent-generated code can introduce vulnerabilities (insecure deps, hardcoded secrets, backdoors) — require code review + SAST/secret-scan on all Codex-authored commits
Data leakage via prompt context: limit auto-included files, enforce .codexignore for secrets/PII
Model version drift: pin codex-1 / GPT-5.4 version in policy; review behavior change before upgrading
Supply-chain risk: Codex Cloud has internet egress (when enabled) — agent could pull malicious packages; gate package installs through internal artifact repo, not public registries
Audit trail of agent actions: every tool call, file edit, and shell command must be logged and attributable to a user identity for forensic replay
