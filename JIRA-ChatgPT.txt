1. Authentication & Authorization

fmSSO (SAML 2.0) is the only trusted identity source; two independent SP trusts — ChatGPT and Atlassian — gated on separate AD groups.
All Jira access runs as the end user via OAuth 2.1 with PKCE; no shared service account path when API tokens are disabled.
Jira permission schemes enforce authorization; OAuth scopes are a ceiling, not a grant.
User provisioning and deprovisioning ride SCIM, introducing a 30–40 min propagation lag.
Admin onboarding requires two separate consents: ChatGPT workspace admin and Atlassian site admin.
MFA enforcement lives at fmSSO only; weakness there compromises the whole chain.

2. Ports, Protocols & Network Paths

All traffic is HTTPS (TLS 1.2+); only outbound 443 required from the corporate perimeter.
Critical FQDNs: chatgpt.com, auth.atlassian.com, mcp.atlassian.com, *.atlassian.net.
Atlassian IP allowlist must include OpenAI's ChatGPT connector egress IPs, sourced directly from OpenAI.
Rovo MCP domain allowlist should restrict connecting clients to chatgpt.com only.
Corporate proxy/SSL-break cannot inspect the ChatGPT-to-MCP Bearer path (server-to-server, off-net).
Deprecated /v1/sse endpoint retires 30 June 2026; standardize on /v1/mcp now.

3. Credential Management

Seven distinct credentials exist in the flow; only OAuth tokens live beyond a single transaction.
OAuth access token: 1-hour Bearer, held in ChatGPT's backend vault, not customer-accessible.
Refresh token rotates on every use, valid 90 days per rotation; token theft is partially self-healing.
Revocation has up to a 60-minute tail; active access tokens survive fmSSO disablement until TTL.
API-token authentication must stay disabled org-wide to force named-user OAuth on every call.
OAuth client secret for the Rovo connector is held by OpenAI; customer cannot rotate it.

4. Infrastructure, Data, Application & Operational Security

Prompts, completions, and retrieved Jira content transit ChatGPT's infrastructure under Enterprise no-training terms.
Rovo MCP is vendor-attested stateless; customer has no enforcement point for that claim.
Data residency must align independently across both vendors — split residency is a compliance risk.
Least privilege at Jira via per-project permission schemes bound to a read-only AD group is the primary app control.
Quarterly review of ChatGPT connector tool allowlist is required as Atlassian adds new tools.
Break-glass runbook must cover org-wide connector disable on both sides plus bulk consent revocation.

5. Logging, Monitoring & Threat Model

Two separate audit logs (Atlassian org + ChatGPT Compliance API) must be joined by user email in the SIEM.
Atlassian audit log captures tool invocations but not prompt content; content visibility lives only on ChatGPT's side.
Build alerts for runaway tool-call rates, off-hours writes, high-sensitivity project access, and 429 bursts.
Primary threats: prompt injection via Jira content, confused-deputy, token theft, rate-limit DoS to tenant.
No admin dashboard exists for Jira API quota consumption; 429s are your only signal.
Revocation and scope-change events across both platforms must be monitored, not dropped silently.

6. GenAI-Specific Security

Prompt injection via retrieved Jira issue content is the top novel risk with no robust mitigation.
Agent autonomy and scheduled tasks must be off by default; require admin approval per connector.
Disable all write-capable tools in the ChatGPT connector unless there's a documented business need.
Cross-connector data aggregation (Jira + Drive + Gmail in one prompt) bypasses per-system DLP.
Jira data transits OpenAI infrastructure; data classification must gate which projects are in scope.
OpenAI's no-training commitment is contractual, not technically enforced by the customer.

7. Risks & Gaps

No channel-aware permissions — user cannot be read-only in ChatGPT while read-write in browser.
Revocation lag up to 60 minutes on active access tokens; incident response must account for this.
No customer-tunable rate limiting; runaway agents can exhaust tenant-wide Jira quota.
ChatGPT session cookie TTL is undocumented by OpenAI — get it in writing from your account team.
Delete-operation restriction in Rovo is unconfirmed in official docs; do not rely on it as a control.
Rovo MCP traffic isolation from shared Jira rate-limit pool is unclear; confirm with Atlassian TAM.
OAuth client credentials managed entirely by OpenAI — supply-chain dependency with no customer rotation.
